# Issue #81：文字工具結果承接

## 使用流程與設計審視

沿用文字清理、移除重複行與逐行排序頁面。結果區提供「以此結果繼續」操作，只有明確點擊才將結果帶入下一個工具；到達後仍需按處理。沒有結果時，承接動作停用。其他文字工具維持原有導覽。

工作區顯示「內容只保留在此分頁；重新整理或關閉後會清除」。各步驟輸入、結果與選項分開保留，既有工具網址和瀏覽器上一頁可返回檢查。另提供原始輸入的可展開區塊及「清除整個流程」。

目標頁已有文字時，在來源結果區顯示具名確認區：取代現有內容、保留現有內容並前往、取消。確認區取得焦點，取消後回到原操作；不使用模態視窗，不攔截背景鍵盤焦點。新的操作及提示提供繁中／英文，手機按鈕可換行。

設計審視結論：避免下一步誤以為已完成處理、避免覆蓋既有編輯、避免將記憶體保留誤認為永久保存。保留現有視覺層級；手機、鍵盤與確認焦點須在實作後驗證。#82 的全站文字文案及複製回饋另案處理。

## 實作邊界

- App 內的 React provider 保存這三個工具的狀態，每次 App 初始化均為空白；不使用模組全域資料，避免 SSR 請求共用。
- 只在 provider 中保存輸入、結果、選項和首次處理的原始內容。不將內容放入 URL、history state、localStorage、sessionStorage、分析或網路。
- 編輯輸入或選項後使先前輸出失效，不能承接過期結果。
- 沿用現有文字 pure functions、LanguageContext 和下載 helper；不增加套件或後端 API。
- 清除會清空三個工具的狀態、原始內容與待確認承接。單獨開啟工具仍可操作。

## 實作與驗證計畫

1. 建立範圍限定的記憶體狀態及共用提示／承接操作。
2. 串接三頁的輸入、選項、結果，補去重／排序結果下載。
3. 使用 code-testing-agent 的聚焦方式，在一份跨頁測試驗證水果名單流程、返回、覆蓋選擇、清除、重新初始化、獨立開啟、雙語與敏感內容未持久化。測試不開子代理。
4. 執行相關測試、完整 Vitest、production build。以實際瀏覽器驗證桌面、手機及鍵盤；記錄 implemented-ui 審視結果。
5. 僅提交本次檔案，沿用 develop 建立 main PR，按使用者要求關閉 #81；不自動合併。
